# ADR-0022: Alerting: Prometheus rules, Alertmanager, SLOs through Pyrra

- **Status:** Accepted
- **Date:** 2026-10-22
- **Drivers:** QD2, QD5
- **Replaces:** D10

## Context and drivers
A user-visible failure must page someone; a cause without user impact must not (QD5). Alert rules must be tested like code (QD2)
and work in both modes from one set of files (QD6). A new service must fall under the alerts and SLOs without edits (QD1).

## Considered options
1. **Prometheus rule files, Alertmanager for routing, SLO burn-rate rules generated by Pyrra** (`pyrra generate`, Pyrra does not run as a service).
2. **Grafana-managed alerts** stored in Grafana.
3. **Hand-written burn-rate rules** without a generator, or another generator (Sloth).

## Decision
Option 1. Rules live in `observability/prometheus/rules/`; compose mounts them into the `otel-lgtm` Prometheus, k3d wraps them into `PrometheusRule`.
SLOs in `observability/slo/`: 99.5 % availability and 99 % of requests under 500 ms over 4 weeks, grouped by `application`;
multi-window burn-rate rules are generated into `observability/prometheus/generated/` and never edited by hand.
Levels: `critical` for SLO alerts only (pager and chat), `warning` for causes (chat), `info` nowhere. Labels `severity` and `team` and a runbook per alert are mandatory.
`observability/check-alerting.sh` runs generation, `promtool check` and `test`, `amtool`, `pint` and the runbook check.

## Consequences
- **Good:** a rule is 5–10 lines instead of 25–30 for a Grafana-managed one; unit tests and convention checks in CI; alerts do not depend on Grafana and its database;
  the files carry over to VictoriaMetrics, Thanos or Mimir. In the outage test the fast-burn alert reached Alertmanager in about 3.5 minutes.
- **Cost:** compose runs its own Alertmanager and a copy of the `otel-lgtm` Prometheus config, to compare on every image upgrade;
  services need the 500 ms SLO bucket; notification receivers are still empty; the SLOs are not confirmed under load (risk R5).

## When to choose differently
- Alerts on logs or SQL data sources, or a move to Grafana Cloud: **Grafana-managed alerts**.
- A tool-independent SLO specification across vendors: OpenSLO; Grafana Cloud: Grafana SLO.
- A team that prefers Sloth's format: Sloth generates the same kind of rules.
